بوابة روضة الخل وابتدائية الكواكب بالعارضة
==========================================

محتويات المشروع
---------------
- index.html / styles.css / app.js : البوابة العامة (التصميم كما هو، والبيانات تُقرأ من قاعدة البيانات).
- admin.html / admin.css / admin.js : لوحة التحكم (دخول باسم مستخدم وكلمة مرور).
- config.js                         : إعدادات الاتصال بـ Supabase (الملف الوحيد الذي تعدّله).
- supabase/schema.sql               : إنشاء الجداول والصلاحيات وحاوية الملفات (يُشغَّل مرة واحدة).
- supabase/functions/admin-users    : خدمة اختيارية لإنشاء المستخدمين من داخل لوحة التحكم.
- assets/                           : الشعار والأصول المرئية.

لا يحتوي المشروع على أي أسماء أشخاص أو أرقام افتراضية؛ كل الأرقام تُحسب من قاعدة البيانات،
وفريق المدرسة يُضاف من لوحة التحكم.


خطوات الربط بـ Supabase (حوالي 10 دقائق)
-----------------------------------------
1) أنشئ مشروعًا مجانيًا في https://supabase.com  (اختر أقرب منطقة، مثل Frankfurt أو Mumbai).

2) من القائمة: SQL Editor → New query → الصق محتوى الملف supabase/schema.sql كاملًا → Run.
   ينشئ هذا: الجداول، سياسات الحماية (RLS)، سجل النشاط، وحاوية ملفات خاصة باسم attachments.

3) إعدادات الدخول: Authentication → Sign In / Providers → Email:
   - أوقف "Allow new users to sign up"   (لا يستطيع أحد إنشاء حساب بنفسه).
   - أوقف "Confirm email".
   - (مستحسن) فعّل "Leaked password protection" إن توفّر.

4) إنشاء حساب المدير الأول:
   Authentication → Users → Add user → Create new user
   - Email:    admin@kawakib.local      (اسم المستخدم عند الدخول سيكون: admin)
   - Password: كلمة مرور قوية (10 أحرف على الأقل، حروف وأرقام)
   - فعّل "Auto Confirm User"
   ثم في SQL Editor شغّل:
       update public.profiles set role = 'admin', full_name = 'اسم المدير' where username = 'admin';

5) Project Settings → API (أو Data API): انسخ
   - Project URL               → ضعه في SUPABASE_URL داخل config.js
   - anon / publishable key    → ضعه في SUPABASE_ANON_KEY داخل config.js
   ⚠ لا تضع مفتاح service_role / secret في أي ملف من ملفات الموقع إطلاقًا.

6) افتح admin.html وسجّل الدخول باسم المستخدم admin.


إنشاء المستخدمين من داخل اللوحة (اختياري)
------------------------------------------
بدون هذه الخطوة: أنشئ المستخدمين من Authentication → Users بالبريد  اسم_المستخدم@kawakib.local
ثم امنحهم الصلاحية من صفحة «المستخدمون والصلاحيات» في اللوحة.

لتفعيل زر «مستخدم جديد» وتغيير كلمات المرور والحذف من اللوحة، انشر الخدمة بـ Supabase CLI:
    npx supabase login
    npx supabase link --project-ref <رمز المشروع>
    npx supabase functions deploy admin-users


الصلاحيات
---------
- مدير  : كل شيء (اعتماد الأعمال، النشر للزوار، الحذف، المستخدمون، الإعدادات، سجل النشاط).
- محرر  : إضافة وتعديل الأعمال والملفات والمسارات والفريق، وحذف ما أنشأه فقط. لا يعتمد ولا ينشر.
- بدون صلاحية: لا يستطيع دخول اللوحة.


ما الذي يظهر للزوار؟
--------------------
- مسارات العمل، وأعضاء الفريق المحددون «ظاهر للزوار».
- الأعمال التي حالتها «معتمد» وفعّل المدير إظهارها.
- أرقام إجمالية فقط. الملفات والمرفقات لا تظهر للزوار إطلاقًا.


إجراءات حماية البيانات المطبّقة
-------------------------------
- سياسات أمان الصفوف (RLS) على كل جدول: الحماية في قاعدة البيانات نفسها وليست في الواجهة فقط.
- حاوية الملفات خاصة؛ تُفتح الملفات بروابط موقّعة صالحة لدقيقتين فقط وللمستخدمين المصرّح لهم.
- منع غير المدير من الاعتماد أو النشر للزوار (مشغّل في قاعدة البيانات لا يمكن تجاوزه).
- سجل نشاط تلقائي لكل إضافة/تعديل/حذف، لا يمكن تعديله أو حذفه من الواجهة.
- قفل مؤقت بعد 5 محاولات دخول خاطئة، وتسجيل خروج تلقائي بعد 30 دقيقة من عدم النشاط.
- الجلسة تنتهي بإغلاق المتصفح (لا تُحفظ دائمًا).
- منع رفع الملفات التنفيذية والسكربتات، وحد أقصى 50 م.ب للملف (قابل للتعديل في config.js).
- حماية من حقن الشيفرات (XSS): كل النصوص تُعرض كنص آمن، وسياسة CSP تقيّد مصادر السكربتات.
- مكتبة Supabase محمّلة بإصدار ثابت مع بصمة تحقق (SRI).
- صفحة اللوحة غير قابلة للفهرسة في محركات البحث.
- تصدير السجل CSV مع حماية من حقن الصيغ في Excel.

النسخ الاحتياطي: الخطة المجانية لا تشمل نسخًا احتياطية تلقائية قابلة للاستعادة؛ صدّر السجل دوريًا
من زر «تصدير CSV»، أو استخدم خطة Pro للنسخ اليومي.


النشر على الإنترنت
-------------------
يفضّل رفع المجلد على استضافة HTTPS مثل Netlify أو Vercel أو GitHub Pages أو Cloudflare Pages
(اسحب المجلد وأفلته). يعمل الموقع أيضًا بفتح index.html مباشرة، لكن الاستضافة أكثر أمانًا.
إذا استخدمت نطاقًا مخصصًا لـ Supabase (غير *.supabase.co) فحدّث سطر Content-Security-Policy
في index.html و admin.html.

للتخصيص: النصوص في index.html، الألوان في أعلى styles.css، والإعدادات في config.js.
